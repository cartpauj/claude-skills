# LocalWP Disconnect

Cleanly undoes everything `localwp-connect` wrote. Reads site facts from the `CLAUDE.md` block — does not re-query LocalWP.

Runs under LocalWP's bundled PHP, same bootstrap as connect.

## Step 1 — Find bundled PHP

Same platform switch as `localwp-connect` SKILL.md: find `$CONFIG_DIR` (dir containing `sites.json`), then pick `$CONFIG_DIR/lightning-services/php-*/bin/$ARCH/bin/php`. Set `LD_LIBRARY_PATH` (and `DYLD_LIBRARY_PATH` on macOS) to the shared-libs dir next to it.

If Local isn't installed, skip PHP bootstrap — you can still run disconnect.php with a system `php` if one exists. If no PHP is available at all, tell the user and stop; disconnect is safe to skip (re-install Local or manually remove `bin/wp*` and the CLAUDE.md block).

## Step 2 — Run disconnect

```bash
"$PHP" "${CLAUDE_SKILL_DIR}/disconnect.php"
```

No flags needed on the happy path. Script reads `./CLAUDE.md` for site path, then:

1. Removes `<site>/app/public/wp-content/plugins/<basename($PWD)>` **only if** it's a symlink/junction resolving to `$PWD`
2. Removes `./bin/wp` and `./bin/wp.cmd` **only if** they contain the `Auto-generated by localwp-connect` header
3. Removes `./bin/` if empty afterward
4. Strips the `<!-- localwp-connect:start --> ... <!-- localwp-connect:end -->` block from `CLAUDE.md`; deletes the file if it becomes empty

JSON output shows what happened for each item, plus a `warnings` array for anything left in place.

## Step 3 — Handle blocked items (optional second run)

If the output contains blocked actions, ask the user and re-run with the appropriate flag:

- `blocked_symlink_elsewhere` → the symlink exists but points to a different project. Offer: remove anyway, or leave it. Remove-anyway flag: `--force=symlink-elsewhere`.
- `blocked_real_directory` → target is a real directory (the user's actual plugin code). **Never auto-delete.** Offer: leave it (default), or the user handles it manually.
- `orphan_kept` → `bin/wp*` exists without the connect header. Offer: remove anyway (`--force=orphan-wrapper`), or leave it.

## Step 4 — Report

Print a concise summary from the JSON: what was removed, what was kept, and any warnings. End with:

- If symlink was removed: "The plugin will disappear from `wp plugin list` on the next WordPress admin load."
- "Start a new Claude session to pick up the unconnected state."

## Guardrails

- **Never delete real directories.** Symlink removal only fires when `readlink` resolves to `$PWD`.
- **Never `rm -rf`.** The script removes files individually and only `rmdir`s an empty `bin/`.
- **Fingerprint before deleting wrappers.** The `Auto-generated by localwp-connect` header is the only trigger for auto-removal.
- **Preserve unrelated CLAUDE.md content.** Only the marker-delimited block is removed.
- **Idempotent.** A second run finds nothing to do and exits clean.
